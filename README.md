# 行程有据

基于 AgentScope 的差旅助手，通过命令行完成出行查询、用户偏好管理、差旅制度问答，以及多目的地旅程的规划、修改和恢复。

核心设计是：**主 Agent 做决策，子 Agent 获取信息，Harness 校验并执行，workflow 保存旅程状态。** 模型负责理解和协调，程序负责状态、数据与执行边界。

## Agent 设计

| 角色 | 职责 |
| --- | --- |
| 主 Agent | 识别意图、拆分旅程、选择候选、协调冲突，组织最终回复 |
| 信息获取 Agent | 根据当前任务调用火车、酒店等查询工具，检查结果并返回摘要 |
| 偏好 Agent | 提取长期偏好更新，区分长期偏好和本次临时要求 |
| 记忆查询 Agent | 查询用户偏好及历史旅程 |
| 制度问答 Agent | 检索本地知识库，回答差旅制度问题 |
| Harness / Runner | 校验模型动作、调度子 Agent、推进状态机、保存断点并检查全程一致性 |

主 Agent 通过结构化 JSON 动作表达下一步，例如查询、提交草稿、修复任务和校验全程。Harness 校验后执行，再把结果交回主 Agent 继续决策。旅程编排采用状态机，任务 ID、版本和状态由程序管理。

信息获取 Agent 内部采用“模型决策 → 工具执行 → 模型检查或总结”的循环。火车和酒店查询是工具，由这个子 Agent 使用。每次委派独立组装上下文，工具过程留在本次子 Agent 上下文中，主 Agent 接收结果摘要和必要的结构化事实。

## 多段旅程如何执行

一份 workflow 表示一趟旅程，里面的 task 表示各段路线。例如“从杭州去北京，再去上海，最后回杭州”会形成三个有依赖的任务；未明确取消返程时，默认考虑返程。

```text
用户需求
  → 主 Agent 识别意图，拆分任务或定位已有旅程
  → Harness 建立或恢复 workflow
  → 主 Agent 决定当前 task 的下一步
  → 子 Agent 查询，结果回填到对应任务
  → 主 Agent 选择候选并提交草稿
  → 推进后续任务，检查日期和路线衔接
  → 全程校验通过后，生成用户回复
```

各任务保存条件、目标、查询结果、草稿和状态。缺少必要条件时，系统保存断点并询问用户；补充后继续同一份旅程。

出现跨段冲突时，主 Agent 可以选择需要重新安排的任务。程序检查修改范围和版本，保护用户明确指定的条件，处理受影响的后续任务，并要求重新校验全程。已有有效组件可以保留，避免无关查询重复执行。

## 记忆与渐进式披露

长期记忆保存用户画像、偏好和旅程；短期记忆保存当前会话的摘要及尚未压缩的主会话消息。临时出行要求保存在旅程条件中，不自动写成长期偏好。

完整 workflow 可以保存大量候选和查询记录，但模型每次只接收当前决策需要的视图：

- **定位旅程**：先读独立的小结索引，让主 Agent 根据用户需求选择 workflow，再加载选中的完整 JSON。正常定位不会逐个读取所有完整旅程。
- **处理任务**：提供任务概览、当前任务的必要条件和精简候选；省略网址、原始接口数据及重复字段，保留选择、比较和校验需要的事实。
- **继续查询**：按需读取后续候选页，复用已有查询缓存；完整数据仍保留，供执行层校验和后续使用。

主会话历史按 token 预算触发压缩，压缩切点位于完整用户轮次之间，保留摘要和未压缩消息。子 Agent 每次委派使用独立上下文，不继承上次委派的对话历史。

会话事件保存在 `events.jsonl`，恢复状态保存在 `state.json`，模型和工具的运行记录保存在 `runs.jsonl`。运行日志用于观测，不直接充当模型提示词。用户数据按身份隔离，workflow 可以跨会话恢复。

## 能力边界

当前旅程规划主要提供火车与酒店地点建议，不执行购票、订房或景点活动安排。酒店地点查询不提供房价、空房和退改承诺。

真实供应商能力取决于接口配置与可用性，现有生产火车接口尚不可用。离线测试和模拟测评的数据不代表真实可购买的票或房间。

系统分别限制上下文、模型调用、任务调度和工具执行，并保留超时与熔断保护。具体配置和校准记录见开发文档。

## 本地运行

使用 Python 3.11，在仓库根目录执行：

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
Copy-Item .env.example .env
```

首次运行时创建 `.env`；已有配置请保留。填写 `LLM_API_KEY`、`LLM_BASE_URL` 和 `LLM_MODEL`；酒店地点与火车接口密钥分别为 `AMAP_API_KEY` 和 `JUHE_TRAIN_API_KEY`。

```powershell
python cli.py
```

按提示填写用户身份和常住城市后，可以直接输入需求，例如：

- “从杭州去北京待两晚，再去上海待一晚，安排火车和酒店。”
- “继续上次的北京行程，把第二段改到周五。”
- “以后酒店优先选全季。”

常用命令：`help`、`history`、`resume`、`preferences`、`status`、`health`、`exit`。`resume` 恢复会话，自然语言请求可以定位并继续已有旅程。

制度问答使用 `.claude/skills/ask-question/data/documents/` 下的演示资料。准备本地嵌入模型后，运行 `python .claude/skills/ask-question/script/init_knowledge_base.py` 初始化知识库。

运行离线回归测试：

```powershell
python -m pytest -q
```
