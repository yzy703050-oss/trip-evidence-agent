# 统一旅行存储

依据：用户同意将 `trips.json` 与 `workflows/{workflow_id}.json` 合并，并明确要求“开始合并”。历史列表展示已完成规划的最新方案，不新增历史版本快照。沿用单代理实施与整体自审。

项目未初始化 OpenSpec；本文记录本次已讨论方案及兼容约束，不创建 OpenSpec 目录。

## 行为与边界

- 旅行状态和历史统一保存到用户隔离的 `workflows/`。新用户不创建 `trips.json`，更新偏好或保存方案均不再写入它。
- 完整工作流只保留每趟旅行的最新版本。历史查询从完成规划的工作流生成，重复完成或修改同一旅行不增加历史数量或目的地计数。规划完成不表示实际出行或订票。
- CLI `history`、上下文历史筛选、记忆查询、目的地统计保留现有入口与返回字段，读取统一数据；未完成的工作流仍供断点恢复使用。
- 已有 `trips.json` 和更早的用户单文件记录迁入统一存储。保留来源文件作为只读备份，不删除用户数据。迁移须可重试、幂等，只有全部保存成功后才写迁移完成标记。
- 旧记录引用已有完整工作流时，以完整工作流为准，避免旧版本覆盖和重复历史。缺少完整工作流状态的旧记录作为明确标记的历史记录保存，不编造可执行任务，不加入活动工作流或恢复入口。旧独立规划结果也通过此兼容入口保存。
- 历史记录与可执行工作流共用存储目录，但由记录类型区分；现有工作流的读取校验、版本比较与原子写入保持有效。
- 清空历史后，重启不会从备份重新导入。保留用户偏好和可恢复工作流；历史清除标记屏蔽清除前记录，之后新完成的规划可以再次出现在历史中。
- `trip.md` 本次保留为可重建摘要，改从统一存储获取旧历史，不再依赖 `trips.json`。此前用户要求的 README 简化保留。

## 技术方案

扩展 `WorkflowStore` 管理独立历史记录、迁移和历史视图。完整工作流历史通过现有任务、确认条件和校验方案投影为现有历史接口的字段。历史记录使用稳定身份、记录类型及原子写入，避免并发迁移覆盖较新内容。工作流查询与恢复过滤历史记录。

兼容加载沿用原优先级：存在 trips.json 时读取它，否则迁移更早的用户 JSON，防止过时备份复活已移除记录。无 ID 的记录按原列表位置区分；同一旧工作流若包含多个版本，选最高版本，同版本选最后一条。身份哈希区分工作流 ID 与历史行程 ID。

`LongTermMemory` 保留 `save_trip_history/get_trip_history/get_frequent_destinations/get_statistics` 接口，委托统一存储；`_save` 只写用户画像。完成工作流时 Harness 不再复制整份方案到第二份历史文件；兼容旧规划结果仍通过统一历史入口保存。目的地和旅行数量由历史视图计算，避免持久化计数漂移。

## 验收

新用户无 trips.json；完成方案直接可查历史；重复规划不重复计数；修改后历史反映最新版本；未完成方案可恢复；旧记录跨重启迁移不重复且备份不变；迁移失败可重试；不完整历史无法作为任务恢复；用户数据隔离；清空后历史不复活；CLI 和记忆查询保持可用。全量测试通过。
