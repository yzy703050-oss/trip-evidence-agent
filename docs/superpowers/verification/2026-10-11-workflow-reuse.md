# 跨会话 workflow 匹配与复用

## 范围与基线

- 用户要求：新会话输入旅行规划时先由模型比较已有 workflow 的日期、目的地与当前时间；唯一匹配自动复用，多个候选或不能确定则询问。
- 用户确认从最新 main 开始修改。工作区通过 Codex 原生工具创建，分支为 `codex/workflow-reuse`，基线 `origin/main` 为 `992ff451b8adefffc6e7b3a029558263ace55f61`。
- 独立开发期间未切换或修改原工作目录；用户随后明确授权本地合并到 main，并推送功能分支创建 PR。
- 项目没有初始化 OpenSpec，因此未创建其结构，也未声称执行 propose/apply/verify/archive；本变更沿用已确认的简短设计，当前代理实施并整体自审。

## 实现与场景核对

- 创建新规划前读取当前用户全部可执行 workflow 的简要身份信息，原聊天摘要不参与注入。
- 有候选时调用 `MainAgent.match_workflow`，比较当前北京时间、原始需求、路线顺序、住宿范围、日期与条件；没有候选时不增加匹配调用。
- 输出限定为 new/reuse/clarify，复用目标必须来自提供的候选，响应无效时停止，避免失败后默认创建重复记录。
- 唯一已完成匹配沿用原 ID、版本与方案，无外部查询；复用说明、历史数据说明和模拟标记保留到最终回复。
- 未完成规划继续原 task；要求最新查询时保留 workflow ID、失效旧缓存并重新查询。
- 多候选询问不改变旅行记录；询问及候选顺序保存在当前 session，恢复后能选择编号；成功执行后清理询问。
- 再次加载复用目标时检查观察到的 revision，保留原有并发更新冲突保护。

## 自审及边界

检查了旅行身份与会话隔离、保存时机、失败时无重复保存、候选编号上下文、复用版本校验、实时查询缓存和回复事实边界。没有自动删除或合并已有重复记录。

模型比较是语义决策，评估通过不能保证所有表达都判断正确；历史很多时摘要输入会增加 token。两个窗口同时读取没有匹配记录并同时新建，仍可能产生重复，当前保留的是原有更新冲突保护，并未增加跨创建的事务唯一性约束。
