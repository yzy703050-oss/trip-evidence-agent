## 测评中发现并处理的问题

1. 首次 RAG 检索在 Windows 中文路径下无法写入 Faiss 索引，却被显示成“没有知识”。增加纯英文数据库目录配置，并将检索异常与真正的空结果区分。复测检索成功。
2. RAG 输出只保存检索片段前 200 字，预算上限恰好在截断位置之后，无法核验答案依据。改为保存完整片段；复测 `rag_grounding` 通过。
3. 记忆查询 Agent 原先忽略画像中的 `hotel_brands`，第一次回答错误声称偏好未正式保存。补全偏好格式化与提示词后，跨会话复测回答正确。
4. 行程预算有两种不同结论：明细下限合计 2520 元，例如高铁 1100、全季两晚 900、餐饮 500、市内交通 150、门票杂费 150，合计 2800 元，**存在 3000 元内的估算组合**；但明细上限合计 3080 元。模型写的“整体约 2600-3000 元”也与分项合计区间不一致。EDD 分别记录可行性与最坏情况下的预算保证。当前 `trip_case.json` 的严格保证检查失败，不能解释为“完全没有预算内方案”。具体车次、酒店与价格仍需实时核验。

## 评审模型与边界

额外调用同一 `deepseek-flash` 模型作质量评审，给出 RAG 5/5、记忆 5/5、行程 4/5；它**漏判了最坏组合的 3080 元超过预算**。因此评审模型只作为补充意见，数字约束以程序检查为准。同一模型评审不具备独立性。

行程中的具体车次、票价、酒店价格、天气和景点预约规则未接入实时核验，本轮不把这些描述视为已证实事实。RAG 质量目前只有一个真实政策问题；尚不能据此推断整体检索准确率。

三个原始会话的 `events.jsonl`、`runs.jsonl` 位于被 Git 忽略的 `data/memory/`，对应 ID 分别为 `eval-rag-final-20261008`、`eval-trip-20261008`、`eval-memory-fixed-20261008`。可用 `python -m evals.v0_memory.runner` 搭配三个 case JSON 复核。
