# V0 记忆系统设计

本文件记录用户在 2026-10-08 确认的设计；项目未初始化 OpenSpec，因此不创建 OpenSpec 结构。

## 行为

- 保留 V0 的意图识别、`agent_schedule` 和确定性调度器。
- 使用 `user_id` 定位用户、`session_id` 定位会话；同一会话可恢复。`turn_id`、`seq` 和 `tool_call_id` 仅用于内部配对与排序。
- 用户消息、模型的工具调用、工具结果、最终回复在发生时逐条持久化。直接调用子 Agent 的行为单独记为运行事件，不伪装成模型工具调用。当前 V0 没有模型工具调用，不制造虚假记录。
- 会话原始事件采用有序追加日志；用户画像、行程记录与会话分开存储。画像可查看和由用户修改；用户明确修改的偏好优先于自动提取。
- 短期记忆从会话日志恢复；向意图 Agent 提供用户可见会话消息与摘要，向子 Agent 只提供必要上下文。内部工具消息按 scope 留给对应 Agent，不能全量注入每个模型。
- 上下文超过预算时，以程序逻辑选择已完成轮次或当前轮的已完成阶段压缩。切点不能落在工具调用与结果之间；未完成工具调用保留原文。摘要记录 `covered_through_seq`，原始事件继续保留。跨会话只选相关摘要与画像。
- 异常时保留已记录事件，不伪造成功回复；工具失败写与调用 ID 对应的失败结果。并行写入仍须获得唯一递增 `seq`。
- 旧版 `data/memory/{user_id}.json` 迁移到新的布局，不丢失偏好、历史行程或有 session_id 的聊天消息。迁移可重复运行，旧文件保留。

## 存储

`data/memory/{user_id}/profile.json`、`trips.json`、`sessions/{session_id}/events.jsonl` 与 `state.json`。事件包含 `seq`、`turn_id`、`scope`、`type`、`role`、`content`、时间；工具事件额外包含 `tool_call_id`、调用名称和状态。AgentScope 的 `Msg` 在项目边界转换成该格式。

## 验收

TDD 覆盖用户与会话隔离、持久化恢复、旧数据迁移、事件顺序、工具配对、合法压缩边界、失败恢复和提示词上下文过滤。EDD 记录意图计划与实际 Agent 调用、RAG 质量、回答质量、延迟、模型调用量、token 与成本；无密钥时可运行离线确定性部分，模型质量评测单独运行。
