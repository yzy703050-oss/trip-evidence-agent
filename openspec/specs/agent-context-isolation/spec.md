# agent-context-isolation Specification

## Purpose
为差旅规划的主 Agent 和子 Agent 建立清晰的上下文边界，使工具执行过程仅占用本次子任务的临时上下文，同时让主 Agent 获取可验证的结果摘要，维持行程依据、来源身份以及跨任务的信息隔离。

## Requirements

### Requirement: 子 Agent 每次委派使用独立临时上下文

系统 SHALL 为每次子 Agent 委派独立组装上下文，仅包含本次明确传入的任务、必要业务事实及权限内的查询资料。子 Agent SHALL 在本次委派内使用工具结果继续模型调用，但 MUST NOT 跨委派继承之前的模型对话，MUST NOT 持久化用于下一次继承的对话记忆，MUST NOT 对子上下文执行摘要压缩。读取长期偏好和历史业务资料不属于继承子 Agent 对话。

#### Scenario: 重用同一个子 Agent 实例
- **WHEN** 同一实例先后处理两个独立任务
- **THEN** 第二次输入仅包含第二个任务显式提供的上下文，不包含第一次的工具往返或内部消息

#### Scenario: 同次委派中的工具循环
- **WHEN** 子 Agent 请求工具并在返回后继续调用模型
- **THEN** 本次上下文保留完整调用和对应结果，没有子上下文摘要调用

### Requirement: 主 Agent 接收可验证的子结果摘要

系统 SHALL 将子结果以结构化摘要提供给主 Agent，包括结论、状态、缺失条件和完成任务必需的事实及引用；MUST NOT 将原始工具调用消息、原始工具返回文本或完整候选缓存直接作为主模型历史。系统 SHALL 保留用于候选选择、来源核对和行程校验的业务数据，摘要投影 MUST NOT 改写完整业务存储。

#### Scenario: 工具返回冗长内部文本
- **WHEN** 子 Agent 的工具返回包含大量内部文本以及有效候选
- **THEN** 主模型输入只包含任务所需摘要和有效候选引用，不包含内部文本；程序仍能从业务存储校验选择

#### Scenario: 子结果尚未完成
- **WHEN** 子 Agent 返回部分结果或查询失败
- **THEN** 摘要保留状态和缺口，不将失败描述为已完成或将未知报价描述为已核实

### Requirement: 审计日志与模型上下文分离

系统 SHALL 保留按用户和会话隔离的原始用户消息、用户可见答复、工具审计和运行记录。日志共享会话存储 MUST NOT 导致子工具记录进入主上下文压缩的输入或计数。新写入的主会话最终事件 SHALL 仅保存用户可见答复、必要业务摘要以及行程身份/版本引用，MUST NOT 嵌入完整 workflow、完整候选缓存或整轮执行结果。完整业务数据 SHALL 由权威业务存储保存，事件精简 MUST NOT 修改调用方收到的完整结果。旧完整业务结果事件 SHALL 兼容读取，供模型使用时仍采用精简投影。

#### Scenario: 会话恢复后组装主上下文
- **WHEN** 旧会话包含大量子 Agent 工具事件和完整业务结果 JSON
- **THEN** 主 Agent 获得主会话消息和摘要，子工具审计不进入主历史或主摘要

#### Scenario: 行程结果写入新会话事件
- **WHEN** CLI 收到创建、修改或部分完成的完整行程结果
- **THEN** 最终事件只保存回复、必要摘要和行程引用，权威行程、返回结果及当前展示仍完整
