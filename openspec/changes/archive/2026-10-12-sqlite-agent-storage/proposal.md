## Why

用户已确认引入数据库统一解决当前文件存储问题：会话最终事件重复保存完整 TripPlan、日志追加和上下文读取反复扫描历史、偏好旧副本覆盖新更新，以及行程提交与小结更新缺少共同提交边界。当前本地 CLI 场景采用 SQLite，保留自研 Agent 内核并建立明确的一致性、查询和迁移机制。

## What Changes

- 将用户画像与偏好、会话及事件、运行观测、TripPlan 和兼容旅行历史迁移至 SQLite；不增加数据库服务或 ORM 依赖。
- 完整 TripPlan 继续保留结构化 JSON，但身份、版本、状态和轻量小结以可查询字段保存；行程与小结同一事务提交，保留原有版本及候选引用校验。
- 新会话最终事件仅保存最终回复、必要业务摘要及行程 ID/版本引用，不嵌完整 workflow，不改变调用方拿到的本轮完整结果。
- 事件采用直接插入、唯一约束和有界读取；模型上下文仅读取摘要未覆盖的会话消息，工具审计与运行记录按需读取。
- 偏好按字段更新，保留用户明确设置和删除优先级；会话状态按明确字段更新并检查异步摘要写入的旧版本冲突。
- 提供可重复、安全且可验证的旧文件导入；保留原文件，迁移成功后 SQLite 成为权威源，禁止运行期双写和数据库故障时静默退回旧文件。
- **BREAKING（内部存储）**：现有 JSON/JSONL 文件路径不再是运行期读写接口；依赖这些路径的测试、评测和辅助代码改用存储 API 或显式导出。CLI 用户操作和 Agent 业务动作保持兼容。

## Capabilities

### New Capabilities
- `transactional-agent-storage`：SQLite 持久化、并发保护、事件查询、状态更新和旧数据迁移。

### Modified Capabilities
- `workflow-summary-discovery`：以数据库小结查询替代独立文件索引，与权威快照共同提交，保留先定位后加载及版本保护。
- `agent-context-isolation`：新最终会话事件不保存完整业务结果；保留原始用户消息、用户可见答复及独立工具审计，兼容旧完整结果事件的投影。

## Impact

主要涉及 context 下的存储、记忆和摘要组件，cli.py 的会话事件保存，相关回归测试及 evals/scripts 中的文件路径依赖。新增数据库连接、schema 与迁移模块；调整忽略规则避免提交数据库及 WAL 文件。RAG 独立项目、供应商实现、模型适配、规划/修复状态机和资源预算逻辑不在改造范围。面向用户的 TripPlan 只读详情/候选查询以及 AgentScope 移除仍是后续独立变更。
