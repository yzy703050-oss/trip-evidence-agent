## Why

当前把子 Agent 工具事件计入会话压缩，同时按 5/10 轮截取历史，可能提前压缩或遗漏尚未被摘要覆盖的消息。用户要求独立子上下文与结果摘要，以 token 阈值触发主会话完整轮次压缩，并明确超限停止行为。

## What Changes

- 子 Agent 每次委派使用独立临时上下文，任务内保留工具往返，不压缩、不跨调用继承对话记忆。
- 主 Agent 只接收结果摘要及必要业务事实和引用；工具原文留在审计日志和业务存储。
- 取消生产上下文的消息数/轮数截取；按 token 阈值压缩连续完整已完成用户轮次。
- 当前轮及固定输入无法通过压缩旧轮次降到阈值以内时，停止本轮并建议将旅程分段规划；保留已有结果。
- 保留会话恢复和原始日志，兼容旧轮内摘要边界。
- 用户明确豁免单轮超限停止及分段提示的专项测试；其他场景执行 TDD 和回归。

## Capabilities

### New Capabilities

- `agent-context-isolation`：子 Agent 临时上下文、工具过程隔离与主结果摘要。
- `token-session-compaction`：token 阈值、完整用户轮次压缩、连续恢复及超限分段提示。

### Modified Capabilities

无。项目首次初始化 OpenSpec，尚无既有主规格。

## Impact

涉及 context、CLI、主 Agent、Harness、WorkflowRunner、子 Agent 技能脚本和相关测试。新增统一预算和结果投影模块，保持完整业务对象、提供商接口及用户隔离。不增加子 Agent 持久化对话，不自动拆旅程或重放外部请求。
