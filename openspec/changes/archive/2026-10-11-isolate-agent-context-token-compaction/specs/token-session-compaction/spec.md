## Purpose

为差旅助手提供基于 token 预算的主会话历史管理，使用完整用户轮次作为压缩边界，避免轮数截断导致上下文空档，支持原始记录恢复，并在不可压缩的当前任务超限时清楚告知用户将旅程分段处理。

## ADDED Requirements

### Requirement: token 阈值决定压缩时机

系统 SHALL 根据当前主模型输入的 token 计数或明确标识的 token 估算判断是否超过可配置阈值，包含指令、已有摘要、未压缩主消息、当前需求和实际携带的业务数据及工具定义。MUST NOT 使用固定消息数或轮数触发压缩或淘汰尚未摘要的主消息。子 Agent 工具原文不属于主模型输入；不同请求累计计费用量不等于当前上下文大小。

#### Scenario: 很多短对话未超过阈值
- **WHEN** 超过 10 个完整用户轮次的主上下文仍未超过阈值
- **THEN** 系统保留全部未压缩主消息，不因轮数触发摘要或截取

#### Scenario: 历史使当前主输入超过阈值
- **WHEN** 主上下文超过阈值且存在可压缩的完整旧轮次
- **THEN** 系统以摘要替换连续旧轮次前缀，重新核算剩余输入

### Requirement: 只在完整用户轮次之间切分主会话

系统 SHALL 将一条用户请求及其子任务和最终答复视为同一个用户轮次。压缩 SHALL 只覆盖连续的已完成旧轮次前缀，MUST NOT 在当前活动轮的子任务完成、工具调用或工具返回处切分。前缀 MUST 包含其中各轮次的全部主消息，且不跨越尚未完成的轮次。

#### Scenario: 当前轮完成多个工具阶段
- **WHEN** 当前用户轮次尚未生成最终答复，但已有工具结果或阶段完成事件
- **THEN** 这些事件不构成主会话压缩切点，当前轮完整保留

### Requirement: 摘要覆盖与会话恢复连续

系统 SHALL 用摘要覆盖边界与剩余完整主消息共同恢复上下文，不遗漏未被摘要覆盖的可见消息；原始日志 SHALL 保留。摘要失败、为空或存储失败时 MUST NOT 推进覆盖边界。已有轮内摘要 SHALL 兼容读取，其未覆盖的同轮主消息不得丢弃；后续新压缩必须以完整轮次结束为边界。

#### Scenario: 摘要后重启
- **WHEN** 用户恢复存在已保存摘要的会话
- **THEN** 摘要与未覆盖的主消息连续衔接，没有固定轮数截取造成的空档

#### Scenario: 生成摘要失败
- **WHEN** 摘要模型失败或返回空文本
- **THEN** 原摘要和覆盖边界保持不变，未压缩消息继续保留

#### Scenario: 旧版摘要在一轮内部结束
- **WHEN** 读取已有轮内覆盖边界和 checkpoint
- **THEN** 保留旧摘要及未覆盖主消息，后续摘要只覆盖完整结束的连续轮次

### Requirement: 不可压缩的当前上下文超限时停止并建议分段

系统 SHALL 在每次业务模型调用前检查所属 Agent 的当前输入预算，并在完整输出消费后、后续模型或工具执行前检查本次上下文增长。主 Agent 可先压缩完整旧轮次；若当前轮及必要固定输入仍超过阈值，或子 Agent 本次临时上下文超过阈值，系统 SHALL 停止当前用户轮次，不继续模型调用、工具执行或自动重试，保存已取得的业务结果并告知用户将旅程分段规划。系统 MUST NOT 拆开当前轮压缩或压缩子上下文后继续。用户明确要求不对本条编写或运行专项场景测试。

#### Scenario: 当前任务独立上下文超过阈值
- **WHEN** 当前任务输入或完整输出加入后的上下文超过阈值，且不能通过压缩完整旧轮次降到阈值以内
- **THEN** 系统停止本轮，保留已有结果，提示“本次旅程内容超过上下文预算，已停止本轮处理。请将旅程分段规划，例如先安排第一段，再处理后续路段。”，不自动新建会话或拆分旅程
