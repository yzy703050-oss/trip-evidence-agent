## Purpose

为命令行差旅助手提供独立于数据库查看方式的普通运行日志，使开发者能直接定位启动、请求、模型和工具执行状态及异常，同时限制日志体积并保留现有业务存储和审计语义。

## ADDED Requirements

### Requirement: CLI 初始化有界普通日志

CLI SHALL 在交互启动与独立 health 入口开始时配置 UTF-8 日志，默认路径为项目根目录下 data/logs/runtime.log、级别 INFO。每条日志 SHALL 包含上海时区时间、级别、模块和消息。默认单文件上限 SHALL 为 5 MiB，保留 5 份轮转旧文件。重复配置 SHALL 不造成同一条消息重复写入，不因导入 cli 模块或构造测试对象就在真实目录生成文件。

#### Scenario: 从其他工作目录启动
- **WHEN** 用户从任意工作目录运行项目 CLI
- **THEN** 日志仍进入项目 data/logs/runtime.log，而非当前工作目录

#### Scenario: 重复配置及轮转
- **WHEN** 日志配置被重复调用，或日志超过上限
- **THEN** 每个事件仅写入一次，并按配置轮转，旧文件数量受限

### Requirement: 记录运行摘要与异常

日志 SHALL 记录应用启动及退出、请求处理结果与耗时、模型调用阶段/状态/token/耗时、工具名称/状态/缓存命中/耗时。存在时 SHALL 保留会话与轮次标识用于关联，MUST NOT 自动将完整用户输入、模型消息或供应商载荷作为正常摘要输出。现有程序异常 SHALL 可通过日志定位；新增日志 MUST NOT 替代、取消或改变现有 SQLite 写入和错误传播。

#### Scenario: 一次正常请求
- **WHEN** CLI 完成包含模型和工具调用的一轮处理
- **THEN** 日志可见各阶段摘要和请求耗时，数据库仍保持原观测记录，正常摘要不包含完整用户问题或接口响应

#### Scenario: 请求失败
- **WHEN** 请求抛出异常
- **THEN** 日志包含失败及异常堆栈，原异常处理和数据库观测仍执行

### Requirement: 上下文预算和压缩诊断可直接查看

普通日志 SHALL 记录上下文检查的阶段、所属 Agent、估算或真实计数标记、当前值及预算；压缩发生时 SHALL 记录执行结果、摘要调用次数、完整请求压缩前后大小、覆盖边界及失败/停止原因。API 输入/输出 token SHALL 与上下文估算明确区分，usage 缺失时显示未知，不伪造 token。普通日志 MUST NOT 为说明压缩而复制摘要正文、用户历史或完整模型载荷。

#### Scenario: 压缩后继续执行
- **WHEN** 旧会话历史压缩使完整请求重新满足预算
- **THEN** 文件可见检查及压缩前后数值、覆盖位置和成功状态，后续模型调用有对应 usage/阶段摘要

#### Scenario: 压缩失败或停止
- **WHEN** 摘要生成失败、无安全进展或预算仍未满足
- **THEN** 文件可见失败或停止原因，估算与 API 用量区分，现有状态保护和数据库审计保持
