## Why

用户希望查看普通运行日志时不必直接查询数据库，并明确要求新增普通运行日志。当前 CLI 未配置统一文件日志，运行观测主要通过 SessionStore 写入 SQLite，终端 logging 输出也没有固定归属。

## What Changes

- CLI 启动时配置 UTF-8 普通日志，默认写入项目 data/logs/runtime.log，INFO 级别。
- 记录启动/退出、请求状态与耗时、模型用量摘要和工具执行摘要；既有异常堆栈进入同一文件。
- 日志按大小轮转，默认单文件 5 MiB，最多保留 5 份旧文件，避免无限增长。
- 不记录完整用户输入、模型请求/响应或供应商原始载荷；现有 SQLite 业务与审计记录保持，不迁移或删除数据库表。
- 2026-10-14 用户在 Harness 与压缩修复中再次要求纳入普通运行日志；补充上下文预算检查、压缩前后估算和停止原因，方便直接查看本次修复的执行情况。

## Capabilities

### New Capabilities

- `runtime-file-logging`: 普通日志文件、轮转、CLI 接入与结构化摘要。

### Modified Capabilities

无。

## Impact

新增 utils/runtime_logging.py，修改 CLI 与模型/工具观测的日志输出，新增运行日志测试和 README 说明。不依赖新包，不改变业务规划行为。

用户数据清理是本次用户明确授权的一次本地维护操作，不添加产品删除接口：2026-10-14 用户确认删除所有本地用户数据（含测试用户及旧备份）后，已清空 data/memory 的 69 个文件，验证剩余条目为 0；data/preferences 不存在。代码、配置、模型和知识库保持不动。
