## Context

本次以 proposal 和四项 specs 为正式依据。用户在 2026-10-12 确认内容裁剪而不是新增主读取工具，并补充恢复时先读小结索引、选中后才加载目标 JSON。执行方式沿用单代理。

当前 CandidateStore 保存全量结果，candidate_view 返回一页；主模型直接接收候选。当前恢复/match/TripMemory 都调用 list_all，正常加载和保存会扫描完整文件。当前调度额度是 tasks 数量 × 4 + 4，子查询模型上限 6，委派每任务 3，上下文 6000、输出 8192；这些值只记录现状。

## Goals / Non-Goals

目标：精简模型输入、摘要定位、受控跨段修复、可复核的最终预算。
不新增主原生读取工具，不改变外部失败/模拟策略，不要求外部供应商实测，不给子 Agent 跨调用记忆，不改变 reply_facts 或当前轮次压缩边界。

## Decisions

### 1. 领域视图

project_domain_result 按 train、hotel_offer、hotel_place 分别选字段，保留候选 ID、query/result/task 版本及身份。价格、时刻、站点、名称、报价/地点区别、可用性属于判断事实。距离/评分/取消信息在实际用户条件或相关偏好需要时提供。URL、原始 source、证据、坐标、重复时刻与每候选重复查询条件不默认传。来源仅提供简短 provider/模拟/未核实状态，不能把未知到达日期或无房价酒店变成已验证。

候选默认仍一页，数量和筛选排序沿用。只在 relevant_results 一处携带当前查询候选，latest_child_result 留小结/查询元数据。主 workflow 的 tasks 是轻量索引，current_task 是唯一详细当前任务。校验反馈只含问题和版本，不展开重建全程数据。用户任务条件不可擅自截断。

主到子只传原需求、当前 task/query_requests、条件、偏好、preflight、前段边界及需要的已存当前结果；不传主历史、全部 workflow/其他任务或全部查询结果。子内部查询工具协议和事实存储不变。

### 2. 独立 workflow 小结索引

新增 context/workflow_index.py，用户目录独立 workflow-index.json。每项保留 ID、版本、状态、时间、confirmed_conditions 的必要条件、轻量任务身份/路线/日期及简短小结；不保存候选池、完整草稿、执行审计或原始 source。保存一个 workflow 时从这份已知快照更新对应索引项，不重读其他完整文件。

索引首次缺失或损坏时允许一次从存储重建，以兼容旧文件；正常发现只读索引。读取权威目标仍经过 WorkflowStore.load 的所有权/ID/CAS 约束；索引损坏不可跨用户读取，过期版本不能直接恢复。索引是可重建投影，不取代 JSON。索引更新失败必须标记需要修复并报告日志，不能悄悄采用错误版本；保存后同步在文件锁内完成，旧索引项不能覆盖较新版本。

MemoryManager 的模型发现入口使用索引，Harness 初始化及匹配不再对每份候选 check_workflow。模型以 resume_workflow_id 选择后，Runner 才加载完整目标。活动身份从 state 及索引取得；保留公共 get_active_workflows 的兼容加载接口，但正常提示词路径不调用它。TripMemory 正常摘要修复从索引渲染，显式重建/旧索引迁移可以读取完整快照。历史导入/统计接口保持现有语义。

### 3. 跨段修复

新增受控 repair_tasks JSON：workflow_revision、task_ids、components(train/hotel/schedule)、conflict_codes、reason。必须关联当前真实阻塞问题，目标可以是旧任务，不接受未知 ID/旧版本/无关目标。动作不接受任意条件写入；保留用户固定条件，只清理 proposal/default/derived 中受修复影响的日期供程序重新推导。

程序更新根任务版本，失效修改组件，重绑定经检查未受影响的组件；保留历史结果和有效候选供缓存复用。保存根任务、前后边界及待重验依赖 checkpoint，先完成根任务。改变边界后只重开不满足新边界的依赖，清理该依赖非用户固定的日期，继续按原顺序处理。未改变边界且方案仍有效时保留。修复进行中的 checkpoint 可恢复，不允许 finish 绕过全程校验。重复决策无进展和非法动作保护继续生效。

### 4. 调度与模型资源

新增显式 main_decisions_per_turn：一次合法业务决策消耗一调度步；dispatch、draft、repair、validate、finish 都计入。按当前 task 归因；同 turn 重开不能清零。非法模型请求保留独立拒绝/失败审计，无进展与工具/超时边界独立。旧 main_steps_per_task/main_extra_steps 构造方式兼容，但不再冒充实际模型请求计数。

MeteredModel 记录真实成功请求及 turn/task/子委派作用域，包括初始化、匹配、摘要、最终回复；BudgetedModel 记录输入/同次完整响应预算估算。子模型成功计数只在响应成功完整收集后增加，失败排除。上下文预算包含实际工具 schemas，使用已有估算器并单独标注 usage。

专用校准上下文通过 contextvars 解除待校准应用层 token/模型/调度/委派上限；熔断、无进展、工具、超时、分页不变。服务商硬限制仍存在。全部功能完成后，以可重复离线成功路径采样，各作用域最大值乘二写回配置。最大输出和同次上下文各自观测，不混合不同调用的最大值。辅助子委派单独统计，不替代调度额度。

最终报告注明估算/实际 usage、模型/数据替身及覆盖场景；离线样本是当前测试依据，不能声称测过真实供应商。若两倍值超服务商边界则明确未满足，不能静默截断。

### 5. 验证与迁移

有意义的 TDD 覆盖来源 URL 不进入真实主请求、完整存储不变、必要字段/缺口保留；索引定位不调用无关 workflow.load、匹配和选中恢复、旧索引兼容；旧段修复、组件保留、依赖与恢复；实际调度和成功调用计数；正常路径最大值两倍。

不新增/运行单 turn 超限停止或分段提示专项测试，也不手工触发；普通压缩、业务、计数继续验证。使用保存/模拟候选，供应商失败排查延期。实际全量 pytest、必要静态检查及人工规格核对通过后归档。本安装没有 verify 工作流，不把 validate 当实现验证。

## Risks / Trade-offs

- 索引陈旧：版本校验、原子更新、异常可重建投影。
- 字段裁剪过度：必要事实与缺口测试，完整存储继续程序校验。
- 修复无进展：独立检测与调度额度。
- 离线样本有限：披露最大值对应场景和来源，不声称覆盖未来所有输入。

## Migration Plan

旧 JSON 不删除。首次索引迁移允许扫描一次；此后正常定位/保存从索引工作。新 checkpoint 与限制字段可选，旧协议兼容。实施计划见 docs/superpowers/plans/2026-10-12-compact-travel-context.md。
